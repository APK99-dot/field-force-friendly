# Reports Module

A new **Reports** section reachable from the More page grid. It opens a clean card grid of report types; tapping a card opens that report's screen where the user sets filters, sees a live preview table with a record count and summary, then downloads a professional Bharath Builders A4 PDF.

Access is scoped: admins see all employees/data; non-admin users see only their own data plus their reporting subordinates (via the existing `get_user_hierarchy` function).

## Entry point & navigation
- Add a **Reports** card (icon `FileBarChart`) to the navigation grid in `src/pages/More.tsx` (`allNavigationItems`), routed to `/reports`. Visible to all users (no module gate).
- Add routes in `src/App.tsx`:
  - `/reports` → Reports landing (card grid)
  - `/reports/:type` → individual report screen
- No internal Back buttons inside pages (per project convention) — navigation handled by the report cards and the standard header. The landing grid acts as the hub; each report screen uses a top "Reports" breadcrumb link via the existing header pattern only if already present, otherwise a simple in-page heading.

## Reports landing page (`src/pages/Reports.tsx`)
- Header: title "Reports" + short subtitle.
- Responsive grid of report cards (1 col mobile, 2–3 cols desktop), each card showing: icon, **report name**, **short description**, and a **"Open Report"** button that navigates to `/reports/:type`.
- Seven cards: Attendance, Leave, Expense, Activity, Milestone, Procurement, Payment.

## Shared building blocks
- `src/components/reports/reportPdf.ts` — one reusable PDF builder using the already-installed `jsPDF`, A4 portrait/landscape. It renders:
  - **Header**: Bharath Builders name/logo (logo pulled from `company_profile` if available, else text title), report title.
  - **Filter criteria** line(s) describing applied filters.
  - **Data table** (manual column layout with page-break handling, mirroring the existing pattern in `ExpenseReportGenerator.tsx`).
  - **Summary** block at the bottom.
  - **Footer**: generated date/time + "Generated by <user full name>".
  - Output via existing `downloadPDF` helper from `src/utils/nativeDownload.ts` (works web + native).
- `src/components/reports/useReportScope.ts` — returns the set of allowed user IDs and user list for filters: admins → all active users; others → self + `get_user_hierarchy(self)`. Built on `useUserProfile` / `useProfilePermissions` + a Supabase call. Used to populate the Employee filter and to constrain queries.
- `src/components/reports/ReportShell.tsx` — shared layout for each report screen: title, filter bar, "Generate"/preview action, record-count line ("Showing N records"), summary cards, preview table, and a **Download PDF** button (disabled until data is loaded).

## Individual report screens
Each is a component under `src/components/reports/` rendered by `/reports/:type`. All query Lovable Cloud directly with the scoped user IDs and chosen filters, show a preview table, compute the summary, and feed the same data to `reportPdf.ts`.

1. **Attendance** (`attendance` table) — Filters: date range, employee, site/project, status. Columns: employee, date, check-in, check-out, total hours, status. Summary: total present, absent days, avg hours/day.
2. **Leave** (`leave_applications` + `leave_types`, `users`) — Filters: date range, employee, leave type, status. Columns: employee, leave type, from, to, days, status, approved by. 
3. **Expense** (`additional_expenses` + `expense_categories`) — Filters: date range, employee, category, status. Columns: employee, date, category, amount, status, approved by. Summary: total, pending amount, approved amount.
4. **Activity** (`activity_events` + `project_sites`, `activity_types_master`, `users`) — Filters: date range, site/project, milestone, activity type, employee. Columns: date, employee, site, milestone, activity type, description, hours, status. Summary: total activities, completed vs pending.
5. **Milestone** (`site_milestones` + `project_sites`) — Filters: site/project, status, date range. Columns: site, milestone, planned start/end, actual start/end, progress %, status. Summary: on-track vs delayed counts.
6. **Procurement** (`procurement_orders` + `vendors`, `project_sites`, items) — Filters: date range, site, vendor, status. Columns: PO number, date, vendor, site, items, PO value, status, payment status. Summary: total PO value, paid, pending.
7. **Payment** (`procurement_invoices` + `procurement_invoice_payments`, `procurement_orders`, `vendors`) — Filters: date range, vendor, site, payment status. Columns: PO number, vendor, invoice number, invoice amount, amount paid, balance due, payment reference, bank name, payment date. Summary: total invoiced, total paid, total balance due.

## Design
- Reuse existing shadcn `Card`, `Select`, `Input[type=date]`, `Table`, `Badge`, `Button` components and the Navy & Gold palette via semantic tokens (no hardcoded colors). Mobile-first, matching the reference Quickapp Reports look: bold KPI/summary cards on top, clean preview table below.

## Notes / scope
- Frontend-only: no schema changes required — all needed tables and columns already exist. Reads rely on existing RLS, so scoped queries return only permitted rows; the explicit user-ID scoping is an additional UX filter.
- PDF only (no Excel/CSV), per your choice.

## Technical details
- Libraries already present: `jspdf`, `xlsx` (unused here), `date-fns`, `@tanstack/react-query`.
- Payment data: `procurement_invoices` has no payment columns directly; payments live in `procurement_invoice_payments` (amount, payment_reference, bank/date fields) — the Payment report aggregates paid amounts per invoice and computes balance due = invoice_amount − sum(payments).
- Procurement "items" column will show item count (from `procurement_items`/order items) to keep the table readable.
- Each report lazy-loads its data on "Generate"; the Download PDF button uses the same in-memory dataset to guarantee preview and PDF match.
